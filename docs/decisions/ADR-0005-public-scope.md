# ADR-0005: 공개 범위 — 전체 공개, 단일 모노레포

## 맥락

라이선스(Apache-2.0)는 이미 정해져 있었으나, 공개 범위(전체 vs 코어만 vs 비공개)는 미결이었다. 이 결정은 지금부터 모든 커밋·문서에 내부 맥락 스크럽 규율이 적용되는지를 가르는 되돌리기 어려운 선택이다 — 한 번 공개한 뒤 커밋 이력을 무르는 비용은 크다.

## 검토한 선택지와 트레이드오프

- **코어만 공개, 나머지 비공개**: "핵심 엔진을 타 프로젝트에서 재사용"이라는 목적(P0)에는 코어 공개로 충분하지만, mcp/cc가 비공개면 다른 사람이 docket을 통째로 못 쓴다 — 확산이 안 된다.
- **지금은 비공개, 검증 후 공개 판단**: 처음부터 공개 규율 없이 편하게 쓸 수 있지만, 나중에 공개 전환 시 커밋 이력 전체를 정리해야 하는 비용이 생긴다.
- **전체 공개, 단일 모노레포(채택)**: 네 계층 전부 하나의 공개 리포에서 개발한다. 계층별 리포 분리는 계획에 없다.

## 결정

전체 공개, 단일 모노레포로 확정한다.

## 결과

**얻은 것**: docket 전체(core+mcp+cc+console)를 다른 사람이 바로 가져다 쓸 수 있다. 나중에 공개 전환 시의 이력 정리 비용을 처음부터 회피한다.

**포기한 것**: dogfooding 중 편하게 남기던 내부 맥락(머신명, 실제 실패 사례의 구체적 서술)을 커밋 메시지·코드 주석·README에 못 쓴다 — 발견 경위·소비자 프로젝트명·경로는 별도의 내부 채널(이슈 초안, 핸드오프 메시지)로만 남긴다.

## 재검토 트리거

없음 — 공개 전환은 되돌리기 어려운 결정이라, 이 결정 자체를 재검토하기보다는 공개된 상태를 전제로 운영 규율을 다듬는 방향으로 간다.
