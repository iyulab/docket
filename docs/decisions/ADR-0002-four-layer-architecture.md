# ADR-0002: 4계층 분리와 코어의 소비자 무지 원칙

## 맥락

docket의 실사용 동기는 Claude Code 멀티세션 조정이지만, 설계 목적은 처음부터 "코어 엔진을 타 프로젝트에서도 재사용 가능하게" 하는 것이었다. 이 두 목적이 충돌하지 않으려면 AI 전용 개념(세션, 훅, 토큰 예산)이 범용 작업큐 개념(워커, 토픽, 아이템, 클레임)과 섞이지 않아야 한다.

## 검토한 선택지와 트레이드오프

- **단일 계층(모놀리식)**: Claude Code 지식이 코어에 바로 들어간다. 구현은 빠르지만, 코어를 다른 런타임(`aims` 등)이 재사용하려면 그 지식을 다시 걷어내야 한다 — P0에서 명시한 목적 자체를 포기하는 것.
- **2계층(코어 + Claude Code 어댑터)**: MCP(pull)와 훅(push)이 메커니즘상 서로 다른데 하나의 어댑터에 섞이면, "코어가 소비자를 모른다"는 경계가 어댑터 내부에서 다시 흐려진다.
- **4계층(core/mcp/cc/console), 소비자를 인간/AI로 먼저 가르고 그 다음 pull/push로 가름**: 계층 경계가 메커니즘 경계(pull vs push)와 정확히 겹친다 — 분해가 임의적이지 않다는 신호.

## 결정

4계층으로 분리한다: `docket-core`(모름) → `docket-mcp`(pull, AI 일반) / `docket-cc`(push, Claude Code) → `docket-console`(인간). 단일 리포로 유지하되, 의존 방향 검사·코어 테스트에 Claude Code 부재·어휘 고정([glossary.md](../glossary.md)) 세 장치로 누수를 강제로 막는다. `P-1`(코어는 소비자를 모른다)을 비타협 원칙으로 삼는다.

## 결과

**얻은 것**: 다른 에이전트 런타임·사람 워커·다른 토픽 관행·`aims` 확장이 코어 무변경으로 가능한 구조([architecture.md](../architecture.md) 확장 지점).

**포기한 것**: Claude Code 고유 기능을 코어에 바로 넣는 지름길. 매번 3번 층으로 번역해야 하는 비용을 계속 지불한다([principles.md](../principles.md) P-1 비싸지는 순간).

## 재검토 트리거

단일 리포에서 세 강제 장치 중 하나라도 기계적으로 구현 불가능하다고 판명되면(예: 의존 방향 검사 도구를 못 찾음) 재검토한다.
